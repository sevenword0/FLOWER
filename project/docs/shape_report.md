Generated by `python -c "from biogen.shape_metrics import report"`;
raw numbers in `docs/shape_metrics.json`.

## What these can and cannot claim

There are no digitised reference specimens in this build, so these are
**internal consistency** checks, not accuracy claims against real fish:

- *Silhouette IoU* — does decimation preserve the outline that identifies the
  animal at distance? Needs no external reference, and is exactly the tolerance
  Gate G8 asks about.
- *Proportion / landmark error* — does the generated mesh actually realise the
  ratios and girth profile the preset asked for? This catches a generator that
  silently ignores its own parameters.

Scoring against museum or CT-derived landmarks remains open (limitation #3).

## Two bugs this metric caught

1. **Length measured 9 % long.** Total mesh extent includes the caudal fin,
   but `reference_length_m` is standard length, which excludes it. The metric
   was measuring the wrong thing; it now measures the body group only.
2. **Seahorse depth error read 144 %.** A global bounding box on a taxon with
   a posture curve measures the whole upright S, not body depth. Depth is now
   measured at the station of maximum girth and normalised by the profile's
   peak value — `body_depth_ratio` is defined at girth 1.0, and the seahorse's
   profile peaks at 0.7.

Both were faults in the measurement, not the generator. A metric that is never
run against a case it can get wrong is not a check.
